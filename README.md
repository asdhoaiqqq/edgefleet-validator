# 验证者与边缘节点机群管理平台

## 用途

节点注册与身份、心跳与遥测、离线同步、配置分发与滚动升级、罚没与健康规则告警、远程运维记录。

本仓库是可持续演进的自托管 Go 应用。领域核心位于 `edgefleet/`，命令入口位于 `cmd/edgefleet/`。

```bash
go run ./cmd/edgefleet demo
go run ./cmd/edgefleet version
go test ./...
```

## 技术方向

validator, node-monitoring, device-fleet, p2p-network, telemetry, devnet

## 运行要求

Go 1.26，仅使用标准库，全部行为可在本机 CPU 上离线复现。

## 真实心跳子系统

健康判断不再依赖调用方手工填写在线状态，而是基于平台实际接收并持久保存的
心跳。全部命令在本机离线运行，不依赖任何外部服务。

命令：

```bash
edgefleet heartbeat-receive   # 接收并整批持久保存一批心跳（支持断连补传）
edgefleet heartbeat-query     # 按节点当前遥测（最大序号）查询健康
edgefleet heartbeat-history   # 按节点查询全部历史心跳（序号升序、不重复）
```

通用标志：

- `--data-dir <目录>`：心跳数据目录，默认 `./edgefleet-data`，也可用环境变量
  `EDGEFLEET_DATA_DIR` 指定。
- `--at <RFC3339时间>`：显式指定接收/查询时间（带时区，如
  `2026-10-01T12:00:00+08:00`）；不指定时使用当前时间。
- 各命令均支持 `-h/--help`，帮助中写明输入格式与数据保存位置。

### 输入格式

`heartbeat-receive` 从标准输入（或 `--file`，`-` 表示标准输入）读取 JSON，
三种形态等价：

```json
[ { "node_id": "val-eu-1", "seq": 1, "collected_at": "2026-10-01T12:00:00+08:00",
    "version": "1.26.0", "height": 100, "missed": 0 } ]
```

```json
{ "heartbeats": [ { "...": "..." } ] }
```

```json
{ "node_id": "val-eu-1", "seq": 1, "...": "..." }
```

每条心跳必须**显式提供全部字段**（缺字段即非法，不会默默变成零值）：

| 字段 | 规则 |
| --- | --- |
| `node_id` | 字符串，节点标识，不能为空 |
| `seq` | 大于 0 的整数；同一节点内可跳跃、可乱序；不同节点可重复使用 |
| `collected_at` | 带时区的 RFC3339 采集时间，不得晚于本次接收时间 |
| `version` | 字符串，节点版本，不能为空 |
| `height` | 区块高度，允许 0，不得为负 |
| `missed` | 累计漏签数，允许 0，不得为负 |

成功返回新增与重复数量，例如 `{"inserted":2,"duplicated":1}`。

### 语义

- **重复**：同一 `node_id`+`seq` 且各字段值完全相同（`collected_at` 按同一
  时刻比较，不同时区写法等价）。
- **冲突**：同一 `node_id`+`seq` 但内容不同，明确报错并禁止覆盖。
- **整批原子**：批次内同样识别重复/冲突；任一条非法或冲突，整批不生效，
  不创建节点、不改变已保存数据。
- **迟到与补传**：迟到记录照常保存；但当前遥测始终取该节点**最大序号**的
  记录，因此刚补传的过期遥测不会被判为健康。
- **在线判定**：最新采集时间距查询时间不超过 60 秒为在线（恰好 60 秒仍在线，
  超过即离线）；查询时间早于该记录时明确报错；从无心跳的节点返回
  `has_telemetry=false` 与“无遥测”，不以零值表示健康。
- **版本/漏签**：`heartbeat-query --expected-version V --tolerated-missed N`
  沿用现有 `Evaluate` 规则（版本相等；漏签数不超过允许值）。

### 持久化与并发

数据保存在数据目录内：

- `heartbeat.log`：仅追加的帧日志，每帧带 CRC32；一批为若干心跳帧加单个
  提交帧，一次写入并 `fsync`，接收成功即整批已落盘。
- `heartbeat.lock`：`flock` 跨进程互斥。同一数据目录允许多个命令进程同时
  接收与查询：并发提交相同记录只新增一次，并发冲突只有一份成功，查询永远
  看不到半个批次。
- **崩溃恢复**：未提交的写入尾部在下次打开时截断；已提交数据、重复识别与
  当前遥测选择在平台重启后保持一致。
- **损坏处理**：已提交数据 CRC/结构损坏时明确拒绝读取与继续写入，不会静默
  清空，也不会当作空库运行。
- 日志超过阈值时在锁内以临时文件 + `fsync` + 原子改名方式压缩，去重后
  结果不变。
